# スーツケースサイズ診断ツール 公開パッケージ

GitHub Pages にそのままアップロードして公開するための一式です。すべて単独で動作する静的ファイルで、外部リソース（CDN・外部フォント等）は使っていません（GA4 の計測タグのみ外部読み込み）。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | ツール本体（旅行から選ぶ診断＋手持ちのスーツケースの機内持ち込みチェック） |
| `guide.html` | 解説ページ（1泊10Lの目安・日数別早見表・S/M/Lの呼称のちがい・機内持ち込みのルール・3辺の測り方） |
| `sitemap.xml` | 検索エンジン向けサイトマップ |
| `robots.txt` | クローラー向け設定（sitemap の場所を通知） |
| `README.md` | このファイル |
| `work/test-calc.js` | 計算ロジックの単体テスト（Node で実行。公開時はアップロード不要） |

## 計算方式

- 基本の量 ＝ 10L ＋ 10L × 宿泊数（1泊なら20L、3泊なら40L、7泊なら80L）
- 容量の真ん中の値 ＝ 基本の量 ＋ 季節の調整（夏・リゾート −10L／春秋 ±0L／冬・寒冷地 ＋15L）＋ お土産の調整（少なめ ±0L／ふつう ＋5L／多め ＋10L）
- 容量の範囲 ＝ 真ん中の値の−5L〜＋10Lを5L単位に丸めたもの（下限は15L、上限は350L）
- サイズの呼称 ＝ 真ん中の値で判定（30L未満はSS、30〜40LはS、40〜60LはM、60〜80LはM〜L、80〜100LはL、100L以上はLL）
- 機内持ち込みの目安 ＝ 推奨容量の上限が40L以下なら「機内持ち込みできるサイズが中心」、下限が40Lを超えるなら「預け入れが基本」、そのあいだなら「小さめを選べば機内持ち込み可」
- 手持ちのスーツケースの容量の概算 ＝ 3辺（cm）の積 ÷ 1000 × 0.9（角の丸み・フレーム分を考慮）
- 機内持ち込みの判定 ＝ 各辺の上限と3辺合計の上限の両方を満たすかどうか。路線区分ごと（大手100席以上：55×40×25cm以内・合計115cm以内、国内線小型機：45×35×20cm以内・合計100cm以内、ピーチ：合計115cm以内、ジェットスター：56×36×23cm以内・合計115cm以内）
- 受託手荷物の目安 ＝ 3辺合計が158cm以下なら国際線・国内線ともサイズ内、203cm以下なら国内線はサイズ内・国際線は超過の可能性、203cm超ならどちらも超過の可能性

## 公開手順（GitHub Pages）

1. GitHub にログインし、新しいリポジトリを作成する（名前は `suitcase`、Public）
2. このフォルダのファイル（`work/` を除く）をすべてリポジトリ直下にアップロードする（`Add file` → `Upload files`）
3. リポジトリの `Settings` → `Pages` を開く
4. `Build and deployment` の Source で `Deploy from a branch` を選び、Branch は `main` / `(root)` にして `Save`
5. 数分待つと `https://mini-tools-lab.github.io/suitcase/` で公開される

## GA4について

既存ツールと同じく、GA4プロパティ「mini-tools-lab」に suitcase 用のウェブストリームを作成し、測定IDを取得して `index.html` と `guide.html` の `<head>` 先頭に gtag.js のタグを埋め込む。測定IDが取得できたらタグ埋め込み版を再アップロードする。GA側の内部エラー等で進めない場合は無理をせず、翌週の実行時に再試行する。
